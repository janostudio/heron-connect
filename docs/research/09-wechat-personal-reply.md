# 微信个人号「本人身份代答」调研

> 调研日期：2026-09-03
> 目标：让 heron 引擎以「本人身份」自动回复别人发来的个人微信私聊（对方看到是「我」在回，而非机器人）。
> 结论先行：**该目标在「免费 + 合规 + 稳定」约束下无法实现**。唯一已跑通且零风险的是官方 ClawBot（ilink）机器人方案，但回复方是「机器人」而非「本人」。

---

## 1. 结论先行

你最初期望的链路是：

```
其他人微信 ──发消息──> 我的微信号（本人）──> heron 在背后替我回复
```

这条链路**必须有一个程序「登录你的个人微信号」**才能拿到私聊消息、并以你身份回复。而「登录个人微信号」这件事，微信官方只提供了一种方式——ClawBot（ilink），且它登录后是一个**独立机器人**，看不到你的私聊，做不到「本人代答」。

结论：**「本人身份代答」和「安全合规」互斥**。你只能在两条路里二选一：

| 路线 | 回复方身份 | 免费 | 合规 | 稳定 | 封号风险 |
|---|---|---|---|---|---|
| **A. 官方 ClawBot（ilink）** | 机器人「ClawBot(AI)」 | ✅ | ✅ 官方 | ✅ | 无 |
| **B. 第三方 iPad 协议** | 你的微信号本人 | ❌ 付费 | ❌ | ❌ | 高 |

---

## 2. 背景：微信官方只开放了什么

微信从未开放「个人号自动回复」的官方 API。2026 年腾讯唯一做出的开放，是 **ClawBot 插件 + ilink 网关**——允许在你的个人号上「挂一个 AI 机器人」，而不是「把你的号变成机器人」。

关键边界（来自官方调研文档 9.1 节）：

> iLink 是「允许一个 Bot 挂在你的号上」，不是「把你的号开放成 Bot」。
> 它不劫持你的账号登录态，代价是视野极窄：看不到好友列表、看不到你和别人的对话、不能主动群发。

推论：ilink **天生不能主动推送、不能以本人身份回私聊**，只能做「有问必答」的机器人。

---

## 3. 方案全景（6 大类）

### 3.1 协议模拟类（登录你的号，模拟客户端）

| 方案 | 原理 | 环境 | 成本 | 状态 |
|---|---|---|---|---|
| Gewechat | 云端 iPad 协议 | Linux Docker | 免费 | ❌ **2025 官方停维**，服务/镜像下线 |
| Wechaty + PadLocal | iPad 协议 | Linux | 付费（按月 token） | ⚠️ 存活但收费 |
| WeChat4IPad 等 | iPad 协议 SDK | 云 | 付费（加微信咨询） | ⚠️ 灰色商业 |

### 3.2 Hook 注入类（注入真实微信客户端，读内存）

| 方案 | 原理 | 环境 | 状态 |
|---|---|---|---|
| WeChatFerry (WCF) | DLL 注入 Windows 微信 | **必须 Windows** | ✅ 活跃，但需 Windows |
| WeChatRobot (TonyChen56) | C++ Hook 注入 | Windows | ✅ |

### 3.3 网页版 API 类（已死）

- openwechat / wechat-go / itchat：基于网页版微信 API
- ❌ 微信网页版 **2023-11 正式关闭**，此类方案已失效

### 3.3b 数据库破解类（读本地 SQLite，不可发消息）

| 方案 | 原理 | 用途 | 状态 |
|---|---|---|---|
| PyWxDump 等 | Hook 拿密钥 → 解密本地 SQLite | 导出/查看聊天记录 | ⚠️ 需 Hook，微信升级易失效 |
| WeChatMsg / chatlog 类 | 解密聊天记录 | 只读导出 | ⚠️ 只读，不能代答 |

- 只能**读**历史消息，**发不了消息**（发消息仍需 Hook 或协议）
- 拿密钥本身就要 Hook 微信进程，封号风险与 WCF 同档
- 微信 4.0（NT 架构）换成 SQLCipher + 设备绑定密钥，破解难度大增
- 结论：本质是「Hook/逆向」子集，不解决「本人代答」的核心（回复）

### 3.4 RPA 类（视觉识别，非协议）

- 微信 4.0 RPA 框架（YOLO + OCR + 数据库监听，零侵入）
- ⚠️ 较新（2025），封号风险相对低，但笨重、延迟高、不稳定，仍需一台能跑微信客户端的机器

### 3.5 Linux 微信客户端方向

- 腾讯**没有官方 Linux 版微信**（官方文档明说）
- 仅统信 UOS 微信（ItChat-UOS 钻网页版接口空子，已基本失效）
- 无成熟稳定的「Linux 微信 + hook」开源方案

### 3.6 官方合规类（非个人号）

- 企业微信 / 公众号 / ClawBot（ilink）
- ClawBot 已在 heron-connect 跑通

## 4. 关键事实：微信正在系统性打击协议库

2025 年微信官方发布《针对违规获取及利用微信终端用户数据行为的打击公告》，Gewechat 官方仓库（Devo919/Gewechat）随即**停止维护**：

> 本项目已停止维护。Gewechat 的历史运行服务、Docker 镜像、部署方式及技术支持均不再提供。

这不是「理论封号风险」，而是**正在发生的封杀**。同类 iPad 协议方案（PadLocal、WeChat4IPad）面临同样命运。

---

## 5. 核心矛盾（一句话）

**「以本人身份回复」和「安全合规」互斥：**

- 微信官方允许的方式（企业微信、公众号、ClawBot），回复方都是**别的身份**
- 唯一能「本人身份回复」的方式（iPad 协议 / Hook），**全部违反微信协议，有封号风险**

这不是调研不够全，而是微信产品设计决定的——官方不允许程序以个人号身份自动收发消息。

---

## 6. 针对「给自己用」的推荐方案

你的场景是**给自己用**（不是做产品给他人）。据此推荐：

### 首选：官方 ClawBot（ilink）—— 已跑通

```
别人微信 ──> 你的 ClawBot 机器人 ──> heron 引擎 ──> 回复
```

- **已完整跑通**：heron-connect 内置 `platform/weixin`，扫码登录，微信发消息 → heron 回复（本文档调研当日已验证全链路）
- 优点：免费、官方、零封号风险、稳定
- 缺点：对方加的是「ClawBot(AI)」机器人，不是你本人
- 适用：「自己用」场景下，让家人/朋友加你的机器人问 heron，够用

### 备选：企业微信（若想「正经做服务」）

- 企业微信支持微信用户跟企业身份对话，体验接近「跟你聊」
- 合规、稳定、支持多用户
- 缺点：需企业主体认证，身份是「企业」不是「个人号」

### 不推荐：第三方 iPad 协议 / Hook

- 付费 + 封号风险 + 项目随时死（Gewechat 就是前车之鉴）
- 即使做了也可能白做（微信一升级协议就失效）

---

## 7. 关于「heron-connect 新增 gewechat 胶水层」的结论

曾评估在 heron-connect 新增 `platform/gewechat/`（个人号代答适配器），结论是**不落地**：

1. **架构可行**：heron-connect 的 platform 层与 agent 层分离清晰，胶水层只需实现 `core.Platform` 接口的 4 个方法（Name / Start / Reply / Send），完全不用管 heron CLI 调用细节。
2. **但底层通道已死**：Gewechat 服务端停维下线，写了也连不上任何可用服务。
3. **根本约束未变**：个人号代答必须有东西「登录个人微信号」，这一步 heron-connect 无法承担，只能依赖第三方协议（正在被打击）。

## 8. 附录：heron-connect 现有 weixin 平台（ilink）技术要点

- 位置：`platform/weixin/`
- 注册：`core.RegisterPlatform("weixin", New)`
- 登录：`heron-connect weixin setup`（扫码拿 token，写回 config）
- 收消息：`getUpdates` 长轮询（35s hold）
- 发消息：`sendmessage`（需 `context_token` 原样带回）
- 已实现：文本/图片/文件/语音(ASR 文本)、typing 状态、CDN AES-128-ECB 加解密、消息去重、超长拆分、Session Guard(-14 暂停)、限流退避(-2)
